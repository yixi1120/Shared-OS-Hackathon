# Seller Soak Test Report

## 结论

Seller Runtime 已完成一次超过两小时的本地持续运行。账本保存 32,272 笔唯一交易，全部为 `delivered`，没有未完成记录，SQLite 完整性检查通过。该测试验证了本地 Seller API、订单幂等、冲突重放拒绝、来源降级和交付路径，不代表真实 SharedNet 可达性或 Arena credits 结算。

每笔交互都会并发重放同一订单、提交一次变更后的冲突请求，并检查公共事件不能伪造可信 provenance。因此 32,272 笔成功交互同时代表 32,272 次安全重复请求、32,272 次幂等冲突拒绝和 32,272 次来源降级检查。

## 发现的问题

首分钟吞吐为 22.59 笔每秒，整段观察平均吞吐降至 4.16 笔每秒。原因是 `SellerService.quote` 为判断首购状态，每次都调用 `Ledger.list()` 加载全部历史交易。随着账本增长，该路径形成 O(n²) 扫描。

测试最初使用 `launchctl submit` 脱离临时终端。该方式在命令退出后自动重启，并用覆盖模式重新打开日志。首次测试数据仍完整，但最终 JSON 日志被后续重启清空。发现后已移除该任务；今后的持续测试必须使用单次运行器和独立输出目录。

## 已完成修复

账本新增 `buyer_id` 索引和 `has_buyer` 存在性查询，报价不再加载整张交易表。修复后的 30 秒磁盘账本基准完成 848 笔交互，平均 28.15 笔每秒；10 秒与 20 秒快照分别为 29.77 和 28.89 笔每秒，未观察到原来的即时衰减。
