## 验证证据

- 上游原始测试：14项通过。
- 接入后完整测试：37项通过；仅一个第三方依赖的弃用提示，无测试失败。
- 原有 Arena Harness：9个场景均符合预期；成功场景合规，预设失败场景按预期报告违规。不能把“预期失败被识别”说成故障已经自动恢复。
- 三类本地 API 运行输出：`local-runtime-results/`，其中 `run-summary.json` 保存实际时间及结果。
- 示例 API 全链耗时约7.132毫秒，仅本机内存账本测试；不是生产SLA，也不是两小时持续测试。
- 本地评分直接来自现有 `telemetry.py`；未沿用旧离线包中硬编码的93.2示例值。

## 发现但未擅自替其他负责人定稿的问题

### 1. 目录参考价格与报价基价不一致

`seller.py` 目录为6/8 credits，`PricingPolicy` 默认统一基价12。默认参数下首购12，老买家13。此次没有改变报价公式，目录明确标注参考价格不构成实际报价；付款必须使用 Runtime ask_price 或已接受的 negotiated price。思棋与雅婷仍需统一实际基价与目录价。

### 2. 旧冻结文本和实际模型不同

实际代码包含 `requested`、可选 amount/latency_ms、可空 evidence_id；没有 provenance。此次不删除或重命名现有模型字段，新增严格订单输入子模型保留 provenance，默认 self_reported，并在交付外围返回来源声明。核心评分模型不变，**来源权重和签名真实性均未实现**。

### 3. “Verified” 当前不能理解为平台证据核验

代码没有真实 SharedOS grant enforcement、签名核验、SharedNet 节点或网络 credits 转移。身份字段是请求数据；409只检查订单与报价的买家一致，不等于鉴别谁发出了请求。不要把服务名称、receipt、paid 状态或合成 provenance 当作平台背书。

### 4. 暂不宣称全局信誉和反串谋

目录 reputation=0.8/0.78 是上游占位数值，不是统计结果；已在服务说明标注。评分中没有来源权重、跨请求证据去重或独立买家反刷分机制。付款和评分代码虽分离，但不能因此声称已防止所有刷分。

### 5. Arena 无人值守仍需生产验收

当前 Graph 记录失败并报告违规，尚不能保证所有发布、排名、购买失败都自动恢复。SharedOS真实授权、两小时并发运行、故障后恢复和官方API绑定仍属上线前阻塞。冠盛的销售材料不能宣称这些已完成。

## 代码修改边界

- 新增 `sales.py`、模板、Dashboard、演练脚本和测试。
- `api.py` 增加机器目录、自动问答、静态展示及安全的输入校验错误响应。
- `seller.py` 在入账前严格校验并保存必要来源声明，修改报价话术，交付时返回声明及 `verified=false`。
- `graph.py` 只增加介绍字段并填充；未更改购买、排名或故障处理策略。
- **未修改** `strategy.py` 价格公式、`telemetry.py` 评分公式、账本 schema、SharedNet 适配器或任何真实平台配置。

这些修改是具体可审查的本地实现；代码包和补丁可交给团队合入。正式提交、真实节点和生产审计需要团队环境才能继续完成。
